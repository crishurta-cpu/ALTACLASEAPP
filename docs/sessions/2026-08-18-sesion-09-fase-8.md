## Decisiones

1. **`useGastoForm.js` NO creado**: misma razón que en Fase 7 con `useIngresoForm.js`. Lógica de `useState` acoplada al JSX. Carpeta reservada vacía.

2. **Imports de `CONCS` y `CCAT` desde `./constants`**: en el código original, estos se importaban en App.jsx. Ahora se importan directamente en `GastoForm.jsx` e `EditGasto.jsx`. Esto es más limpio: cada feature trae sus propias dependencias.

3. **Input numérico inline (no `FInput`)**: el campo de "Valor" en ambos componentes usa un `<input>` directo dentro de un `<div>` con prefijo `$`. Esto se mantiene por consistencia con el código histórico. `FInput` con `prefix="$"` no soporta el padding custom que se usa aquí.

4. **`NuevoMovimiento` queda en App.jsx**: este componente es el orquestador de los 3 tabs (Ingreso / Lote / Gasto). Sigue siendo cross-feature. Se evaluará moverlo a `app/` en Fase 17 cuando se introduzca el shell de aplicación.

5. **Imports con paths explícitos** desde App.jsx: `import GastoForm from "./features/gastos/GastoForm";`. Consistente con Fases 5–7.
